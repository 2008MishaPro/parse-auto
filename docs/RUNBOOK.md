# Запуск постоянного мониторинга

Проверенная среда: Windows, Node.js 24.19.0, pnpm 10.23.0. Программа запускает `.ts` напрямую; билд не выполняется без просьбы владельца. Runtime-зависимости не нужны: используется native `fetch`. Точные dev-версии закреплены в package.json и pnpm-lock.yaml.

## Конфигурация

`searches.json` — единая рабочая конфигурация любых городов и поисков. `searches.example.json` — проверенный узкий пример. `searches.smoke.json` — два диагностических поиска, включая широкий с бюджетом две страницы; он намеренно остаётся partial и не годится для приёмки полного охвата.

```json
{
  "dataDir": "./data/state",
  "searches": [{
    "id": "cars-1",
    "source": "avito",
    "url": "https://www.avito.ru/moskva/avtomobili/honda/s2000-ASgBAgICAkTgtg2ymCjitg2Oryg?s=104",
    "enabled": true,
    "intervalSeconds": 120,
    "overlapPages": 2,
    "sweepIntervalSeconds": 1800,
    "maxPagesPerSweep": 30,
    "requestTimeoutSeconds": 30,
    "maxCycleSeconds": 90,
    "maxDetailsPerCycle": 0
  }]
}
```

`dataDir` разрешается относительно файла конфигурации; при отсутствии поля используется `./data/state`. ID уникальны и после первого сохранения привязаны к точным `source + URL`. Другой URL/источник требует нового ID; изменение привязки отклоняется до HTTP, в том числе для поиска на паузе или ID, ранее удалённого из конфигурации. Регион, цена, марки и остальные фильтры задаются URL, изменение поиска не требует новой папки или отдельного процесса. URL и его параметры не очищаются автоматически. Сортировка `s=104` подтверждена SSR как «По дате», но устойчивый порядок публикаций не доказан; `publishedAt=null`.

`maxCycleSeconds` ограничивает время одного обхода: целое число от 1 до 86400, по умолчанию 90 секунд. `requestTimeoutSeconds` отдельно ограничивает получение одной страницы. `overlapPages` не может превышать `maxPagesPerSweep`. Примеры example/smoke явно задают общий лимит 90 секунд.

`maxDetailsPerCycle` включает ограниченное автоматическое дополнение характеристик из карточек: целое число 0–10, по умолчанию 0. При 0 карточки автоматически не запрашиваются. Рабочий searches.json задаёт 2; для одинакового source + точного URL применяется максимальный лимит текущих включённых aliases. Настройка применяется при следующем запуске и сама не запускает остановленный монитор.

Начальная загрузка и периодическая сверка обходят доступные страницы до конца либо бюджета страниц/времени. Обычный опрос собирает не меньше `overlapPages` с верхней части, если доступный конец не наступил раньше. `coverage.windowIds` содержит ID только из первых страниц предыдущего завершённого прохода с головы. Если в обязательном окне нет пересечения с прежним окном и есть следующая страница, опрос расширяется в `catch_up` до доступного конца или бюджета. Один известный ID не завершает обход. Исчерпание page budget такого догона записывается как `window_overflow`, возможный gap и требование полного прохода.

Восстановление продолжает непроверенную страницу; завершение одного хвоста не считается новой полной сверкой и не заменяет опорное окно. Отказ, общий deadline и наблюдаемый сдвиг между страницами также сохраняют прежнее окно и полный checkpoint. Legacy-состояние без окна начинает полный проход с головы. Если ID повторился между разными страницами, полезные данные сохраняются, а `pagination_shift` требует нового прохода с головы; полностью одинаковая страница остаётся ошибкой `repeated_page`. Старые/неизвестные даты публикации не отбрасывают новые для нас ID.

Если бюджета не хватает для начального полного прохода, baseline остаётся незавершённым и события подавляются. `baselineNeedsBudgetIncrease/requiredAction` требует увеличить `maxPagesPerSweep` или сузить поиск; `baselineNeedsTimeBudgetIncrease` — увеличить `maxCycleSeconds` или сузить поиск. Счётчик 1500 широкого каталога — предел сайта, а не полное число машин.

Одинаковые `source + точный URL` собираются один раз. Учитываются только включённые aliases: кратчайшие interval/sweep interval и максимальные бюджеты страниц, окна, запроса и цикла. Состояние группы остаётся под однажды выбранным `storageId`: добавление более раннего по алфавиту ID, удаление исходного ID или его пауза не сбрасывают baseline, cursor, известные цены и защиту от повторов. Для новой группы выбирается первый ID в лексикографическом порядке; полностью выключенная группа получает сохранённую привязку, но не делает HTTP. Более широкие/узкие запросы не объединяются.

`searchBindings` сохраняет соответствие каждого известного ID полям `queryKey` и `storageId`, включая aliases на паузе и удалённые из конфигурации. События сохраняют канонический `searchId=storageId`; старые события не переписываются при смене aliases. `coverage.aliases` перечисляет активные aliases последнего выполненного обхода.

Legacy-группа с единственным сохранённым `queryKey` принимается под прежним ID. Восстанавливаются только aliases, ещё присутствующие в сохранённом coverage; забытые до этого среза aliases восстановить нельзя. Старое состояние без `queryKey` можно впервые привязать через его собственный ID, без угадывания URL удалённых поисков. Если у используемого exact URL несколько отдельных legacy-состояний, запуск остановится до HTTP с диагностикой неоднозначности: автоматического слияния baseline, цен и событий нет. До продолжения нужны разбор таких данных или отдельный dataDir.

## Управление

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd monitor start --config searches.json
pnpm.cmd monitor status --data-dir ./data/state
pnpm.cmd monitor export --data-dir ./data/state --format jsonl
pnpm.cmd monitor export --data-dir ./data/state --format json
pnpm.cmd monitor export --data-dir ./data/state --events
pnpm.cmd monitor export --data-dir ./data/state --gaps
pnpm.cmd monitor export --data-dir ./data/state --search-id volgograd-region-under-150k --format json
pnpm.cmd monitor export --data-dir ./data/state --search-id volgograd-region-under-150k --events
pnpm.cmd monitor export --data-dir ./data/state --search-id volgograd-region-under-150k --gaps
pnpm.cmd monitor compact --data-dir ./data/state
pnpm.cmd monitor start --config searches.example.json --once
```

`start` по умолчанию работает непрерывно. Настройки pause/resume (`enabled`) читаются при рестарте. Ctrl+C/SIGTERM отменяет ожидание и HTTP, затем закрывает журнал. Ошибка адаптера даёт retry/backoff, ошибка сохранения останавливает процесс, в том числе одновременно с Ctrl+C или общим deadline. Код 1 означает ошибку запуска/хранения; `--once` возвращает 2 при error/partial, в том числе для alias, не совпадающего с `storageId`. `status/export` читают снимок и журнал, в том числе при активном writer. Пустая новая папка даёт нулевое состояние.

`status` выводит `queries` под каноническими `storageId` и `searchBindings` для разрешения пользовательских ID. Например, `searchBindings["cars-new"].storageId="cars-old"` означает, что состояние нового alias находится в `queries["cars-old"]`. Команда не читает текущую конфигурацию: сохранённые bindings и aliases последнего обхода не доказывают, какие ID включены в отредактированном файле сейчас.

`export --search-id ID` читает сохранённые привязки и разрешает alias в канонический `storageId`. Объявления выбираются по устойчиво сохранённой принадлежности поиску; события и gaps — по каноническому `searchId`. Отбор не использует время запуска, географические имена папок или текущее состояние `enabled`. Неизвестный или пустой ID даёт ошибку, не пустую успешную выгрузку. `--search-id` поддерживается только командой `export`; без него выгружается весь store, включая прежние выключенные поиски. Выгрузка содержит накопленные наблюдения и не подтверждает, что все машины ещё продаются.

Для сохранения статического файла используйте общий каталог выгрузок:

```powershell
New-Item -ItemType Directory -Force ./data/exports | Out-Null
node src/cli.ts export --data-dir ./data/state --search-id volgograd-region-under-150k --format json > ./data/exports/selected-listings.json
```

`status.sources` показывает общий счётчик последовательных отказов и `blockedUntil` каждого источника; дата последнего успешного получения страницы здесь отличается от полного checkpoint query. Health сохраняется до освобождения FIFO/следующего HTTP; успех/empty сбрасывает счётчик, отмена/общий deadline его не повышает. При старом состоянии положительный восстановленный максимум query помечен `legacyEstimate=true`, первый успех снимает признак; точный прежний порядок отказов узнать нельзя. Удаление старого поиска не отменяет сохранённый source backoff.

`status.gaps` и `export --gaps` показывают историю риска пропусков. `--format json` даёт массив, по умолчанию — JSONL; `--gaps` и `--events` вместе запрещены. Каждый период содержит `gapId/searchId/runId/since/until/reason/sequence`; одна причина одного цикла уточняет прежний gapId, разные причины сохраняются отдельно, успех не удаляет записи. `since=null` означает неизвестную нижнюю границу; при переводе часов назад она не выдумывается. Старый пригодный `lastGap` импортируется один раз, прежние утраченные периоды восстановить нельзя. Число gaps не является числом потерянных объявлений.

`compact` создаёт текущий снимок и сокращает журнал без запросов Авито и без чтения конфигурации. Команда получает тот же эксклюзивный writer lock: при работающем мониторинге завершится кодом 1, поэтому для ручного сжатия сначала остановите `start`. При успехе stdout содержит одну JSON-строку с `compacted: true`, `sequence`, числом records и events; baseline/cursor, сами события и их eventId сохраняются. `--data-dir` здесь, как у status/export, разрешается относительно текущей папки; по умолчанию это `./data/state`.

На источник действует FIFO: одна операция адаптера для каталога и карточек, минимум 2 секунды между операциями, общий backoff 10–300 секунд с учётом большего Retry-After. По умолчанию AvitoAdapter использует `AvitoHttpSession`: она дополнительно соблюдает минимум 2 секунды между всеми реальными HTTP-запросами, включая проверку доступа, HTTP-переходы и reload. Мягкие SSR-переходы ограничены тремя, с отменяемой паузой 2 секунды и общим таймаутом страницы; ручные HTTP-переходы также ограничены тремя и тем же origin. Это стартовые ограничения, а не измеренная допустимая нагрузка площадки.

Целевой интервал измеряется от начала цикла к началу следующего; длинный обход может его превысить. Просроченные циклы не создают параллельные дубли. Общий бюджет начинается при старте обхода и включает очередь сохранения, callbacks, FIFO/throttle/backoff, каталожный и карточный HTTP и штатную проверку доступа. Обогащение использует только оставшееся время исходного maxCycleSeconds. Deadline отменяет ожидание/получение следующего результата; запись уже полученных полезных данных с fsync завершается устойчиво, поэтому остановка не обязана уложиться в лимит до миллисекунды. Подтверждённый до deadline доступный конец сохраняет полный успех, даже если финальный commit завершился позже.

`time_budget` — частичный результат обхода, а отдельный `timeout` страницы — ошибка источника. При общем deadline cursor сохраняется, baseline/lastSuccess/lastExhaustedScan не продвигаются; failureCount сохраняется и новый backoff не назначается. Следующий старт после `time_budget` — максимум из начала + interval, завершения + min(interval, 10 секунд) и действующего backoff источника. Например, interval 120 и maxCycleSeconds 5 сохраняют целевой старт через 120 секунд; затянувшийся обход получает короткую паузу перед продолжением. После обычного результата действует начало + interval с учётом backoff.

## Сохранение и события

В dataDir находятся `snapshot.json`, `journal.ndjson` и эксклюзивный каталог `writer.lock`. Старый dataDir только с журналом читается без отдельной миграции. Журнал содержит последовательные page/query batches с SHA-256; страницы, события и cursor сохраняются вместе, затем выполняется fsync. Незавершённый хвост игнорируется читателем и обрезается при следующем открытии writer. Повреждённая committed строка или снимок останавливают чтение/запись; автоматически их удалять нельзя. Падение writer освобождается проверкой PID; живой/неопределённый владелец блокирует второй процесс.

Снимок сохраняет sequence, поиски, привязки aliases, sources, историю gaps, актуальные объявления, принадлежность записей поискам, последние известные цены, ключи уже обработанных страниц, отдельные карточные detailsStates и все события. Старые снимки/журналы без detailsStates читаются с пустой историей карточек; прежние объявления, checkpoint, цены и события сохраняются. Bootstrap сохраняется при запуске monitor до HTTP. При сжатии sequence не увеличивается. Автоматическое сжатие выполняется в очереди store после 1000 новых batches либо 8 MiB журнала после последнего снимка; ручной `compact` доступен независимо от этих порогов. Устойчиво записанный временный снимок закрывается и публикуется через rename, затем так же публикуется сокращённый журнал с привязкой к снимку. Существующий append handle закрывается до замены журнала, после публикации открывается новый. Читатель при конкурентной замене повторно получает согласованную пару; падение процесса между публикациями допускает восстановление из снимка и прежнего журнала. Ошибка сжатия останавливает дальнейшую запись до перезапуска.

Временный отказ Windows при замене читаемого файла повторяется ограниченно (до 20 повторов с паузой 10–100 мс); постоянный отказ остаётся фатальным. Если автоматическое сжатие отказало после commit, этот последний batch/event уже может быть сохранён: перезапуск восстановит его ровно один раз, экспорт событий доступен, повторной доставки stdout нет.

Первичная загрузка не создаёт `discovered`. После baseline новый ID создаёт `discovered`, изменение последней подтверждённой цены — `price_changed`; A→B→A создаёт два события. Неизвестная цена не равна нулю и не создаёт ложный A→null→A. `eventId` устойчив, события доступны через export после перезапуска. Повтор старого page batch не создаёт новый event. Автоматической повторной доставки stdout после падения нет: сохранённые события можно перечитать через export и дедуплицировать по `eventId`.

Сжатие сокращает повторяющиеся данные журнала и объём его replay; события и ключи page replay сохраняются полностью, поэтому общий размер состояния и память всё ещё могут расти. Проверяется восстановление после падения процесса; порядок сохранения при внезапной потере питания Windows пока не доказан. Supervisor доступен; автозапуск после перезагрузки машины не настроен.

## Автоматическое дополнение характеристик

При maxDetailsPerCycle больше нуля ядро после успешного сохранения каталога выбирает объявления с недостающими vehicle-полями из всей сохранённой membership поиска. Отбор не ограничен текущим poll или первой страницей: старые страницы тоже участвуют. Сначала обрабатываются ещё не запрошенные identity в устойчивом порядке membership, затем разрешённые повторы по attemptedAt ASC. Одновременно сохраняются прежний лимит запросов и общий deadline: рабочий maxDetailsPerCycle=2. Неуспешный/неполный каталог, восстановленный хвост, pagination shift или cap источника по-прежнему пропускают карточный этап. Отдельного процесса, очередной БД или региональной папки нет; прогресс восстанавливается по existing receipts.

До карточного HTTP сохраняется claim source+externalId с attemptId, catalogTitle, attemptedAt и retryAt. Он блокирует повтор той же identity между поисками и после перезапуска до завершения/cooldown, даже при другом названии. После результата отдельный receipt сохраняет outcome и последнюю успешно разобранную raw карточку. При отмене или crash pending остаётся видимым, неизвестный исход не повторяется немедленно. Отказы прекращают текущий карточный этап, обновляют общий source backoff и сохраняют retryAt; каталожный checkpoint остаётся подтверждённым.

Экспорт и read-only FileStore.inspect дополняют только null поля vehicle, если title каталога и карточки совпадает точно и два известных vehicle-значения не конфликтуют. При конфликте не переносится даже недостающая марка/модель. Принятые поля получают карточный provenance; необязательный enrichment содержит отдельный observedAt карточки и fields — список дополнений. Обычный observedAt, цена, валюта, название, URL и publishedAt остаются каталожными. Сырые records/membership и knownPrices не переписываются, карточный этап не создаёт discovered/price_changed/details_changed. inspect.detailsStates показывает отдельные receipts/evidence выбранного поиска; CLI export records выдаёт дополненное представление.

Успех при неизменном catalogTitle подавляет повторные запросы, даже если все дополнительные поля оказались null. Новый title, совпавший с уже полученным card.title, тоже не требует GET; другой title может стать кандидатом после общего cooldown. Периодического обновления успешных карточек и TTL характеристик пока нет. Поэтому enrichment.observedAt нужен для оценки возраста дополнений, а прежняя марка/модель не переносятся при изменившемся title.

В coverage.enrichment и диагностических строках details_started/details_result/details_finished доступны selection=saved_search, лимит, кандидаты, число попыток/успехов/ошибок, elapsedMs и stopReason. scopeRecords прежней первой страницы удалён. Сохранённый хвост проходит постепенно, поэтому наличие1130 записей не означает1130 немедленных карточных запросов. Старые исчезнувшие записи остаются кандидатами до отдельной реализации проверки доступности. completed/no_candidates означают завершение этапа, catalogue_not_healthy/unsupported/source_backoff/time_budget/interrupted объясняют пропуск или остановку. source_failure означает карточный отказ и паузу источника; он не отменяет уже сохранённую каталожную выдачу.

## Контрольная сверка карточек

```powershell
node scripts/check-avito-cards.ts --config searches.example.json --limit 3 --report data/reports/card-check.json
```

Скрипт получает первую страницу первого активного поиска Авито и отдельно сверяет до `--limit` карточек; допустимый limit — 1–5. Перед каждым запросом читает сохранённый source blockedUntil без writer; будущая пауза даёт source_backoff до HTTP. Отчёт по умолчанию data/reports/card-check.json. Сравниваются source/ID/title и подтверждённая полная RUB-цена, дополнительно — два известных year/mileage; unknown характеристики отмечены null, make/model не требуются для подтверждения цены. fetchSucceeded отражает успешное получение и parsing отдельно от comparisonStatus: match, mismatch, unverified (нет полной цены), not_compared (нет пригодного ответа). Несовпадение может быть изменением объявления между наблюдениями и не объявляется отказом транспорта. Код 0 означает match всех выбранных карточек; 2 — незавершённую, неподтверждённую или несовпавшую сверку. При отказе карточки проверка прекращается без немедленного retry. Это ограниченная диагностика: watch/writer не запускаются, checkpoint и события не меняются.

`getDetails` адаптера опционален и использует независимый JSON-парсер карточки. Мониторинг запрашивает ограниченное число карточек только при включённом maxDetailsPerCycle и подтверждённом каталожном результате; контрольная сверка выше остаётся отдельной read-only диагностикой. Неподтверждённая цена, отдельные vehicle-поля и publishedAt остаются null; успешная сверка цены требует известной полной цены в каталоге и карточке. Каталог получает год/пробег из строгого title с provenance; марку/модель карточки подтверждает согласованный flat buyerItem.ga. Разбор сохранённых названий в отчёте vehicle-title-preview.json не обновляет DTO задним числом. Обогащение ранее пустых характеристик не является details_changed; изменение через промежуток unknown не устанавливается.

Штатная проверка распознанной страницы HTTP 439 выполняется в одной HTTP-сессии: get → ограниченное вычисление SHA-256 → verify → повторный GET. Сложность допускается от 1 до 5, максимум 2 000 000 попыток; весь путь включён в общий timeout и отменяется Ctrl+C/SIGTERM. Проверка повторяется не более одного раза за получение страницы. При Retry-After немедленный POST запрещён: отказ возвращается ядру для общего backoff. Cookies живут только в памяти текущего экземпляра адаптера; после рестарта сайт может потребовать новую проверку. Cookies/JWT в отчёт и journal не попадают.

В `diagnostics.httpRequests` видно фактическое число HTTP-запросов; `accessCheck=passed` означает успешную штатную проверку. При неуспехе смотрите `accessCheckReason`, HTTP status и outcome. Неизвестная проверка, капча, проблема с IP или продолжающийся отказ требуют отдельной диагностики; success/empty не подставляются.

## Диагностика

| Состояние | Значение / действие |
| --- | --- |
| baselineComplete=false | Начальная загрузка не доказана; событий ещё нет, проверить бюджет/отказ/cursor |
| available_exhausted | Подтверждён конец доступных страниц; это не обещание всего рынка |
| window | Успешный верхний опрос, не новая полная сверка |
| partial | Бюджет, восстановленный хвост, сдвиг страниц или предел источника; смотреть stopReason/gapReason/coverageLimited |
| time_budget / timeBudgetExhausted | Общий deadline; полезные данные и cursor сохранены. Проверить elapsedMs, увеличить maxCycleSeconds или сузить поиск; это не HTTP timeout |
| windowIds / windowOverlap | Опора предыдущих верхних страниц и факт пересечения с ней; первый знакомый ID не завершает обход |
| windowOverflow / catch_up | Прежнее окно вытеснено; догон расширен. Незавершённый догон требует увеличить бюджеты или сузить поиск |
| paginationShiftObserved / pagination_shift | ID повторяются между разными страницами; полный checkpoint не продвигается, требуется последующий полный проход с головы |
| requiresFullScan | Требуется полный проход с головы; завершение сохранённого хвоста само по себе флаг не снимает |
| error | blocked/auth/rate limit/schema/timeout/pagination/DTO; lastSuccess не продвигается |
| gapPossible / lastGap | Возможные недоказуемые пропуски после сбоя, простоя или ограничения; lastGap сохраняется после успешного опроса |
| sources | Сохранённая общая серия отказов/ожидание источника и результат последней каталожной/карточной операции; legacyEstimate обозначает оценку старых данных |
| coverage.enrichment | Итог ограниченного карточного этапа; каталогный checkpoint и события от его отказа не откатываются |
| enrichment.observedAt / enrichment.fields | Время raw карточки и только перенесённые vehicle-поля; observedAt самого объявления остаётся каталожным |
| detailsStates | Отдельные durable claims/receipts/evidence в read-only inspect; success кэшируется по title, pending/retryAt предотвращают немедленный повтор |
| gaps / export --gaps | История всех записанных периодов риска и их оснований; успех не очищает её |
| overdueMs | Просрочка старта относительно сохранённого nextRunAt |
| HTTP 439 | Распознанная штатная проверка выполняется один раз; неизвестная/неуспешная проверка или повторный отказ остаются blocked, не пустой выдачей |

Не удаляйте dataDir для лечения HTTP-отказа: сохранённые страницы/события остаются полезными. Управляемые проверки догона/сдвига не доказывают полноту сайта. Частота 60–180 секунд, длительная память, живой догон, полнота и ручные контрольные сверки ещё требуют E2.
