## E1 — рабочее ядро с постоянным Авито-поиском

- [x] **E1-01 — живой запрос.** Минимальный TypeScript проект, необходимые зависимости и lockfile; URL автомобильного поиска → нормализованные ID/URL/цены. Конкретный запрос из SOURCE_REUSE воспроизведён, выборочные карточки сверены. Этот результат получить прежде обобщения ядра.
- [x] **E1-02 — адаптер и реестр.** Avito реализует контракт ARCHITECTURE; query, страницы, nullable поля и ошибки. Пагинация проверена минимум на двух непустых страницах с различными ID; повтор одной страницы обнаруживается. HTTP/browser заменяемы без смены нормализованного DTO.
- [x] **E1-03 — постоянное расписание.** Сохранённые поиски, отдельный интервал, pause/resume из конфигурации, start/stop. Watch по умолчанию; один запуск не завершает процесс. Одна query не выполняется одновременно; источник имеет общий лимит запросов. Проверены два поиска и несколько последовательных циклов.
- [x] **E1-04 — состояние и события.** Журнал commit/page, ID/цены, baseline и cursor. После перезапуска replay восстанавливает состояние. Первичная загрузка — baseline; новый ID/изменение цены — разные события. A→B→A создаёт два изменения; повтор старого наблюдения не создаёт третье. Вывод событий только после сохранения, с устойчивым eventId.
- [x] **E1-05 — сборка ядра.** CLI status/export, логи отдельно от данных, корректная остановка и возобновление. Запуск без UI, PostgreSQL, бота и ИИ. Проверены реальные циклы и перезапуск, результат отражён в STATE. Программа запускается напрямую, build не выполнялся.

**Результат E1:** запускаемая программа непрерывно следит за Авито и сохраняет наблюдения. Разовый экспорт не закрывает этап. При неработающем запросе исправлять его, не строить будущие экраны.

Открыто после E1: source cap 1500 из примерно 84 тысяч виден, но пригодная стратегия широкого охвата не доказана. Слишком малый page/time budget сохраняет полезное, однако не завершает baseline и требует изменения конфигурации. Snapshot/compaction добавлены в E2; история событий и ключей страниц сохраняется, поэтому общий размер состояния всё ещё может расти. Карточки проверены выборочно; постоянная доступность при иной защите/IP не обещается.

## E2 — охват, восстановление и длительная проверка

- [-] **E2-01 — стратегия обхода.** Реализованы baseline, опрос верхнего окна, периодическая доступная сверка, продолжение хвоста и общий maxCycleSeconds. При вытеснении прежнего окна опрос расширяется; наблюдаемый сдвиг и исчерпание времени/page budget дают partial/gap без полного checkpoint. Известный ID не завершает обход. Для пилота выбран более широкий uncapped Civic: 165 уникальных записей, свежий baseline p1–p4 подтверждён, следующий poll успешен. Неполная последняя страница распознаётся по проверенным SSR свидетельствам; pageCapacity отделена от фактического остатка. Длительную стабильность сортировки проверяет E2-04; стратегия полного охвата общего каталога около84тысяч при cap1500 пока не доказана. Сегментацию применять только при проверенных фильтрах, без дыр на границах.
- [x] **E2-02 — отказы.** Empty отличается от blocked/auth/rate limit/schema/timeout. Общий source failureCount/backoff/Retry-After сохраняется внутри FIFO до следующего HTTP, callbacks и полезной страницы; чередование ошибок query и рестарт проверены. Success/empty устойчиво сбрасывает общую ошибку; cancel/deadline её не увеличивают. Legacy оценка явно помечена до первого успеха. Ошибка записи прекращает новые запросы всех очередей и остаётся фатальной при Ctrl+C/deadline; непроверенный cursor не пропускается. История всех сохранённых причин gaps устойчива до вывода и после успешного опроса. Snapshot/compaction восстанавливаются после crash и write/rename/reopen отказов; старый журнал поддерживается.
- [x] **E2-03 — проверка полноты алгоритма по управляемому набору.** Simulator проверяет всплеск/переполнение окна, вставку между страницами, поднятый ID, позднюю старую/null дату, сохранение окна при отказе/рестарте и legacy state. Deadline в HTTP/FIFO/store/callback/backoff, stop/ENOSPC, медленный fsync, clock rollback и повреждения committed данных проверены. Snapshot/compaction сохраняют membership/known price/eventId/page replay/source health/gaps; смена состава групп сохраняет исходную историю. Общая серия ошибок разных query, Retry-After/reset/restart и все обнаруженные основания gaps проверены сквозными регрессиями. Supervisor crash/stop/IPC/locks/лимиты, положительные/отрицательные свидетельства последней страницы, экспорт выбранного поиска, строгие nullable характеристики и отсутствие ложного details_changed при обогащении добавлены; 365/365 pass. Повтор/цикл курсора, A→B→A и дедупликация проверены. Это полнота заданного тестового набора, не доказательство полноты живого сайта и не новая интеграция.
- [-] **E2-04 — живой пилот 24–48 часов.** Honda-пилот 2026-10-11 13:33–15:49 остановлен по смене задачи; частые 429 и прежние данные сохранены, сутки не зачтены. Региональный run 16:06–17:06 завершил 13 циклов (6 success, 2 partial, 5 rate_limited). После переноса в общую структуру run **17:08:38–17:46:42** завершил ещё 8 циклов: 1 recovery со сдвигом, затем полный sweep 23 страниц и шесть обычных poll — всего 7 success, без terminal HTTP refusals/падений/дублей. requiresFullScan=false, checkpoints и история сохранены; монитор штатно остановлен по просьбе владельца для разработки следующего среза. Это 38 минут, суточная устойчивость не доказана. Не менее 24 часов требуют фактической оценки records/events/ошибок/RSS/интервалов/gaps и независимых сверок; elapsed и ожидание не отмечать как «тест прошёл». Перед расширением остаётся незавершённая длительная приёмка; runId/PID/команды в STATE.
- [ ] **E2-05 — приёмка и возможность расширения.** Типовые проверки/typecheck проходят; build выполняется только по явной просьбе владельца и до неё не считается проверенным; результаты пилота и пределы охвата записаны. Тестовый адаптер зарегистрирован без веток по имени площадки в ядре. CLI/config/вывод и хранение документированы. Нет скрытого ограничения «только первая страница» и ложного обещания 100% сайта.

**Результат E2:** проверенное ядро + Авито с постоянным поиском, понятными ограничениями и восстановлением. Полноту управляемых тестов можно доказать; полноту сайта без стабильного полного канала нельзя объявлять абсолютной. Непригодный для задачи охват/интервал означает незавершённую приёмку и конкретное решение, а не переход к ИИ.
