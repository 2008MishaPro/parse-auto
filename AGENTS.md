# CarRadar — поручение агенту

## Цель текущей работы

Реализовать минимальное ядро постоянного мониторинга и первую интеграцию Авито. Поиск живёт до остановки: получает страницы, ждёт настроенный интервал, повторяет сбор, сохраняет состояние и восстанавливается после перезапуска. Разовый экспорт — только диагностический режим.

Текущий объём: TypeScript + Node.js + pnpm, CLI, ядро, Avito adapter, постоянное файловое состояние, события и диагностика. Зависимости выбирать по реально работающему способу получения данных. Версии/lockfile закрепить. Сначала живой запрос Авито и небольшой работающий срез; затем обобщение ядра. Не создавать тяжёлый каркас до первой выдачи.

Дром, Авто.ру, Юла, PostgreSQL, Fastify API, React/Reatom, ТГ/ВК, рыночная оценка и ИИ — дальнейшие подключения. Сейчас их не реализовывать. Не требовать четыре источника для приёмки текущего ядра + Авито.

4. После законченного среза обновлять ROADMAP, STATE и CHANGELOG. STATE содержит текущую задачу, блокер, проверки и точное следующее действие. Старые записи изменений не стирать.

## Правила реализации

- Один процесс ядра; адаптеры — модули с общим контрактом. Добавление площадки = adapter + регистрация, без новых условий по имени площадки в ядре.
- Ядро отвечает за сохранённые поиски, расписание, обход, состояние, сравнение и события. Адаптер — за запрос, extraction, pagination и нормализацию данных площадки. Ни один адаптер не отправляет уведомления.
- Сначала используй подходящие механизмы из SOURCE_REUSE. Закрепи донор/commit и лицензию перенесённого кода. Новые решения обосновывай задачей/проверкой, а не названием паттерна.
- Сбор работает непрерывно по умолчанию. Не останавливается после одной выдачи/первого знакомого ID. Циклы одной query не накладываются; лимиты и backoff соблюдаются.
- Unknown — null; source + externalId — identity. Поднятие/первичная загрузка не считаются новой публикацией. publishedAt и наше observedAt различаются.
- HTTP отказ, капча, timeout и неизвестная разметка — отдельные ошибки, не пустой успех. Конкретные транспорт и требования доступа проверять живым запросом, не копировать все зависимости донора.
- Сохраняй полезные страницы сразу; полный checkpoint не продвигай через пропущенную страницу. Сначала устойчивое сохранение состояния/события, затем внешний вывод. Повторный replay не создаёт второй event.
- Неполный обход и периоды возможных пропусков видны. Полная обработка тестового набора не доказывает 100% всех объявлений сайта.
- Короткие регрессии обязательны для дедупликации, A→B→A цены, пагинации, перезапуска и сбоев. Fixture tests не заменяют live smoke. Фактические результаты фиксировать без секретов.
