Atomic runDir lock не снимается при живом/непроверяемом записанном child; writer lock не обходится. Единая регистрация в integrations/registry.ts. Нет автозапуска после reboot/watchdog зависшего child; окно fork→publishPID защищено writer lock/IPC, абсолютная атомарность PID не заявляется.

Ни один из этих признаков не доказывает неизменность живой выдачи.
- Checksummed snapshot.json + append-only journal.ndjson: sequence, fsync до подтверждения, устойчивые page/events/cursor, replay, truncated tail recovery и остановка при committed corruption. Старый журнал поддерживается без отдельной миграции. Эксклюзивный Windows dataDir lock проверен с живым и аварийно завершённым процессом.
- Автоматический snapshot/compaction после 1000 новых batches или 8 MiB журнала; queued ручной compact в CLI без HTTP/config. Сначала temp/fsync/close/rename снимка, затем журнал с anchor(sequence, snapshotChecksum); sequence не увеличивается. Сохраняются per-query membership/knownPrices, baseline/cursor/coverage, все eventId и ключи page replay. Старый префикс под новым снимком проверяется без повторного применения; читатель повторяет чтение при новой паре. Кратковременный Windows rename отказ при чтении повторяется ограниченно, постоянная ошибка останавливает writer.
- События discovered/price_changed/details_changed; baseline тихий, A→B→A даёт два изменения, stale/equal/page replay не дублируют event. A→null→A не создаёт ложное изменение цены. CLI start/status/export, --once только диагностика.
- Постоянный searchBindings связывает все ID одинакового source/точного URL с исходным storageId. Отключение/удаление исходного ID и добавление более раннего по алфавиту сохраняют query/baseline/cursor/membership/knownPrices/page replay. Регистрация всей конфигурации, включая disabled, атомарно сохраняется до HTTP; ранее использованный ID нельзя назначить другому фильтру. getQuery/updateQuery/commitPage разрешают alias в исходный ID; searchId/eventId старых и новых событий остаются исходными. CLI status и live-отчёты показывают bindings; coverage.aliases — включённые ID последнего завершённого обхода.
- Старый журнал/снимок без bindings поддерживается. Уникальная query с тем же queryKey принимается даже без прежних ID в config; сохранённые coverage.aliases тоже регистрируются. queryKey=null можно принять только под тем же ID, прежний фильтр проверить нельзя. Несколько старых query одного затронутого ключа дают явный отказ до HTTP без объединения историй; забытые legacy aliases восстановить нельзя. Повреждённые привязки/неканонические committed batches отвергаются reader/writer.
- SourceState отдельно хранит failureCount/blockedUntil/lastAttempt/lastSuccess/lastOutcome страницы адаптера. Ошибки разных query складываются; success/empty устойчиво сбрасывают общий счётчик и ожидание. FIFO сохраняет health до resolve, следующего HTTP, полезной страницы и callbacks. ## Блокер и пределы

Блокер сверки E1-01 снят живым получением трёх desktop-карточек и сравнением ID/полной цены. Поддерживается только наблюдавшаяся штатная проверка: одна попытка, сложность 1–5, максимум 2 млн nonce, отмена и общий timeout. Неизвестная проверка/капча, явная IP-блокировка, превышение бюджета и повторный отказ остаются blocked/error, не пустым успехом. Retry-After запрещает немедленный служебный POST. Cookies не сохраняются на диск; после рестарта сессия восстанавливается обычным новым запросом/проверкой.

Широкий автомобильный каталог сообщает примерно 84 тысячи основных результатов, но даёт лишь 1500/30 страниц. Диагностический page budget 2 в searches.smoke.json и отдельный time budget 5 секунд в data-cycle-smoke намеренно не закрывают baseline и не производят discovered. Конец доступного каталога не доказывает полный охват сайта. Сдвиг без повторов ID также может остаться ненаблюдаемым; управляемый simulator не доказывает полноту живого каталога.

Более широкий пригодный фильтр и supervisor реализованы/проверены; Honda-пилот остановлен досрочно, суточная проверка не пройдена. Региональная выдача завершила полный sweep 17:14, затем монитор остановлен 17:46 по просьбе владельца; длительная стабильность требует фактической проверки. Полный общий каталог с cap1500 ещё не покрыт. Source checkpoint сохраняет общий счётчик независимо от query; для прежних данных до первого успеха возможна только явно отмеченная legacy оценка. Новая история хранит все подтверждённые записи риска, но из старых данных импортируется только последний пригодный lastGap: потерянная история не восстанавливается. Количество gaps не означает количество потерянных объявлений. Unknown timestamps не разрешают остановку по watermark.

Snapshot сокращает повторяющиеся batches, сохраняя всю историю events/page replay и записи: общий размер состояния и память всё ещё могут расти. После ошибки auto-compaction последний batch может быть уже durable, даже если вызывающий получил ошибку; экспорт сохранит событие, stdout автоматически не повторяется. Temp-файлы после аварии не служат входом восстановления и могут остаться на диске. Подтверждены аварии процесса; сохранение metadata rename при внезапной потере питания Windows не доказано.
