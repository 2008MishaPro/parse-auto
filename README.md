# CarRadar — ядро мониторинга + Авито

Минимальная CLI-программа на TypeScript и Node.js: постоянно получает автомобильную выдачу Авито, сохраняет страницы, сравнивает ID/цены и восстанавливает состояние после перезапуска. Web, бота, БД и ИИ пока нет.

Обзор возможностей, архитектуры и ограничений для планирования развития: [PRODUCT_AND_ARCHITECTURE.md](docs/PRODUCT_AND_ARCHITECTURE.md).

Рабочие данные, архивы, сырые логи и зависимости не входят в Git. Сводка живых проверок сохранена в [monitoring-trials-2026-10-12.json](docs/reports/monitoring-trials-2026-10-12.json); остальные пути `data/...` в документации относятся к локальным материалам. После клонирования монитор начинает с пустого состояния и создаёт `data/` при запуске.

## Запуск

Нужны Node.js 24.19+ и pnpm 10.23.0. TypeScript запускается напрямую; сборка не нужна и без просьбы владельца не выполняется.

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd monitor start --config searches.json
```

`searches.json` — единая рабочая конфигурация. Регион, марки, цена и другие фильтры задаются URL каждого поиска; интервал и бюджеты — его настройками. Сейчас включён поиск Волгограда и области до 150 000 ₽ всех марок, включая ВАЗ, с интервалом 300 секунд (5 минут). `searches.example.json` сохраняет проверенный узкий пример Honda S2000 в Москве. Остановка — Ctrl+C. Изменения конфигурации применяются при перезапуске; `enabled=false` ставит поиск на паузу. Для другого URL/источника используйте новый `id`: состояние связано с исходным запросом. Добавление города или фильтра не требует отдельной папки, процесса или изменения ядра.

`maxDetailsPerCycle` задаёт число дополнительных карточек за цикл: целое от 0 до 10, по умолчанию 0. Рабочему поиску задано 2. После успешного каталога кандидаты выбираются из всего сохранённого списка данного поиска, включая прежние страницы. Сначала идут ещё не запрошенные ID в порядке сохранённой принадлежности, затем разрешённые повторы по времени прежней попытки. Первая страница не ограничивает очередь. Используются оставшийся общий бюджет времени и общая пауза источника. Успешные карточки с неизменным названием не запрашиваются снова; периодического обновления пока нет.

Одинаковые URL одного источника собираются один раз; их бюджеты карточек объединяются максимумом. Добавление, отключение или удаление их ID сохраняет общую историю, цены и точку продолжения. `status` показывает постоянные привязки ID к исходному поиску; ранее использованный ID нельзя назначить другому URL.

Для постоянной работы supervisor запускает один общий сборщик без ограничения срока, до остановки. Перед повторным запуском дождитесь завершения действующего supervisor и дочернего сборщика. Команды управления и отчёта:

```powershell
pnpm.cmd supervisor run --config searches.json --run-dir ./data/run
pnpm.cmd supervisor status --run-dir ./data/run
pnpm.cmd supervisor stop --run-dir ./data/run
node scripts/pilot-report.ts --config searches.json --run-dir ./data/run --report ./data/reports/pilot.json
```

Рабочие каталоги общие для всех поисков:

```text
searches.json    настройки поисков
data/state/     объявления, цены, события, точки продолжения и история пропусков
data/run/       состояние supervisor и логи сборщика
data/exports/   сохранённые выгрузки
data/reports/   диагностические отчёты
data/archive/   материалы завершённых проверок
```

По умолчанию команды используют `searches.json`, `data/state`, `data/run`; отчёт записывается в `data/reports/pilot.json`. Прежняя история Honda и регионального поиска сохраняется в общем состоянии; Honda-поиски выключены. Точный статус запуска и результаты переноса — в `.agent/STATE.md`. Архивы прежних запусков и конфигураций предназначены для разбора проверок, рабочий запуск использует `searches.json`.

При сбое дочерний сборщик восстанавливается после его завершения, без второго владельца данных. Команда stop отправляет запрос; supervisor ждёт сохранения состояния и сообщает stopped после закрытия процесса. После пяти быстрых сбоев или достижения порога логов процесс останавливается с причиной. Подробности — RUNBOOK и STATE.

```powershell
pnpm.cmd monitor status --data-dir ./data/state
pnpm.cmd monitor export --data-dir ./data/state --format jsonl
pnpm.cmd monitor export --data-dir ./data/state --search-id volgograd-region-under-150k --format json
pnpm.cmd monitor export --data-dir ./data/state --search-id volgograd-region-under-150k --events
pnpm.cmd monitor export --data-dir ./data/state --search-id volgograd-region-under-150k --gaps
pnpm.cmd monitor compact --data-dir ./data/state
pnpm.cmd monitor start --config searches.example.json --once
```

Карточки дополняют недостающие автомобильные характеристики при согласованном названии/известных значениях. Export сохраняет марку и модель после новой выдачи с пустыми полями, показывает отдельное `enrichment.observedAt/fields` и источники полей. Цены и события сравниваются по каталогу; отказ карточки отражается отдельно в `coverage.enrichment` и общей паузе источника.

`export --search-id ID` выбирает объявления по сохранённой принадлежности поиску; alias разрешается в канонический ID. События и gaps выбираются по тому же каноническому ID. Без `--search-id` экспорт включает весь store и историю выключенных поисков. Это накопленные наблюдения, а не гарантированно актуальный список доступных машин; отбор не зависит от времени запуска или имени каталога.

Обычный `start` работает до остановки. `--once` — диагностический режим; код 2 означает неполный/неуспешный обход. Первая загрузка — baseline без событий о новых публикациях. События выводятся в stdout после сохранения; диагностика — в stderr. Обнаружение нового ID означает новое наблюдение, а не доказанную дату публикации.

## Проверенный срез

Чистый тест интервала 300 секунд завершён 12 октября, 20:01:32–20:26:32 МСК, за 1500.039 секунды. Система остановлена по duration, exit0, attempts1, childPid=null; writer/supervisor locks отсутствуют. Сохранены 1132 объявления, 0 событий и 4 обогащённые записи. Успешных обходов выдачи 4/5, циклов без ошибки каталога или карточки 2/5. Страниц 30, наблюдений 1432, native HTTP 42. HTTP 429: каталог 1, карточки 2; HTTP 403 не наблюдался. Gaps 1, resumeCursor=null, requiresFullScan=true.

В этой короткой пробе пять минут показали лучший сбор выдачи:4/5 успешных обходов вместо1/5 на3 и4 минутах, получено4 карточки вместо2. Нагрузка послеbaseline около0.58 HTTP/мин против2.41/2.67. Однако осталось3 HTTP429 (1 каталог/2 карточки), только2/5 циклов прошли без ошибок обоих этапов, требуется свежая полная сверка. Текущие300 секунд оставлены; долгосрочная устойчивость и оптимальный интервал не установлены. [Итог пяти минут](docs/reports/monitoring-trials-2026-10-12.json), [сравнение 3/4/5](docs/reports/monitoring-trials-2026-10-12.json). Прежние state/run/exports и config240 сохранены в before-five-minute-test-2026-10-12-200125. Код не менялся, билд и полный набор тестов не запускались. Предыдущие проверки ниже относятся к другим условиям.

2026-10-12 выполнен новый15-минутный прогон с очищенными рабочими результатами и полным архивом прежней истории. Три каталожных цикла успешны, накоплено1137 записей;5 из6 карточек обработаны, одна HTTP429 отложена с сохранённой паузой. Система штатно остановилась. Свежие результаты — data/exports/listings.json, итог — data/reports/quick-test-summary-2026-10-12.json; короткий прогон не заменяет длительную приёмку.

2026-10-11 получены реальные страницы 1, 2 и 30 автомобильного каталога, а также узкая выдача из трёх машин. Непрерывный smoke двух поисков отработал два цикла с интервалом около 120 секунд. Состояние, ошибки и конкретные результаты проверок — в `.agent/STATE.md`.

Общий лимит обхода `maxCycleSeconds` по умолчанию 90 секунд. При его исчерпании полезные страницы и продолжение сохраняются, результат виден как partial. Вытесненное верхнее окно расширяет догон; наблюдаемый сдвиг страниц не считается полным успехом. Живой лимит 5 секунд и восстановление после перезапуска проверены.

Состояние автоматически сохраняется в снимок после 1000 новых записей журнала или 8 MiB, затем журнал сокращается. Ручной `compact` выполняется при остановленном мониторинге. События, цены и защита от повторной обработки сохраняются; общий объём истории может расти. Обогащение проверено релевантными тестами: 201/201, затем после исправления валидации DTO — только затронутые 55/55; typecheck без emit прошёл. Живой сбор на копии состояния и перезапуск получили три карточки, сохранили марку/модель без повторных запросов и новых событий. Отчёты — data/reports/enrichment-summary.json и enrichment-*-tests.txt; основное состояние неизменно. После изменений проверяются затронутые участки; весь набор автоматически не запускается. Перенос в общую структуру сохранил SHA-256 файлов состояния и полный status. Последний монитор штатно остановлен по просьбе владельца; история сохранена. Точные результаты и текущие ограничения приведены в STATE.

Общий счётчик отказов Авито и срок ожидания сохраняются до следующего запроса. Удаление поиска и перезапуск не сбрасывают их. `status` показывает состояние источника и историю возможных пропусков; `export --gaps` выгружает эту историю отдельно. Такие периоды описывают риск, а не доказанную потерю объявлений.

Карточный HTTP 439 исправлен для наблюдавшейся проверки: адаптер сохраняет cookies в памяти, проходит штатную проверку и повторно получает страницу. Три карточки вернули HTTP 200; ID и полные цены совпали с выдачей. Проверить отдельно: `node scripts/check-avito-cards.ts --config searches.example.json --limit 3`. Это диагностика, она не меняет сохранённые поиски и события.

Каталог заполняет год и пробег из двух строгих наблюдавшихся форм названия, включая «битый», и указывает происхождение полей. Карточка дополнительно принимает марку/модель из согласованных отдельных SSR атрибутов; неизвестное остаётся null, слова названия не делятся на марку и модель. Автоматической очереди карточек нет. Старые сохранённые записи не переписываются: новые поля появятся при фактическом наблюдении. Заполнение неизвестных характеристик не выдаётся за изменение объявления.

Первый исполняемый срез E1 проверен. Широкая выдача Авито ограничена 1500 доступными объявлениями при примерно 84 тысячах основных результатов; E2 с проверкой охвата и пилотом 24–48 часов ещё открыт. Неизвестная проверка, капча, IP-блокировка и оставшийся отказ дают явную ошибку.
